# 台股資料與分析

上游的 `stock-analysis` 技能只涵蓋印度與美股；這個技能補上台股的資料來源、慣例與收集工具。
兩者可以一起用：分析框架（多因子、同業比較、盈餘品質、治理）照 `stock-analysis`，
台股特有的資料與單位照本技能。

## 鐵律

1. **不編數字。** 每個數字都要寫出處與期間（例如「公開資訊觀測站 115 年 6 月營收」「114 年合併財報 Q4」）。
   找不到就寫「無資料」並說明需要什麼。
2. **第一手來源優先**：公開資訊觀測站（MOPS）、證交所、櫃買中心的公告與財報。
   財經網站、新聞只當找資料的線索，數字不以它們為準。
3. **單位與日期**：官方資料多為**千元**；日期多為**民國年**（1150730 = 2026-07-30，11506 = 2026 年 6 月）。
   每個表格標明單位與西元日期。
4. **合併 vs 個體**：有子公司的公司一律用合併財報，並明寫。
5. **不給個人化投資建議**：不說「該買／該賣」、不給目標價或進出場點。可以說明數據、同業比較、風險。
   回覆結尾附一句「以上為資料整理，非投資建議」。

## 收集資料（給 App／排程用）

```bash
python3 scripts/tw_stock_fetch.py list                        # 看有哪些資料集
python3 scripts/tw_stock_fetch.py fetch --db data/tw_stock.db  # 抓全部（約 15 秒，含限流間隔）
python3 scripts/tw_stock_fetch.py latest --db data/tw_stock.db --code 2330
```

- 官方 API 只給**最新快照**，沒有歷史查詢 → 歷史要靠每天排程自己存。
  GitHub Actions 範本：`assets/tw-stock-daily.yml`（交易日收盤後跑，資料庫存在 Release 附件，不進 git）。
- 內建限流（每次請求間隔 ≥3 秒＋隨機）、指數退避重試、SQLite WAL、同日重抓不重複。
- 原始每一列以 JSON 整筆保存（官方欄位名稱可能改），分析時再挑欄位。
- 月營收欄位例：`營業收入-當月營收`、`營業收入-去年同月增減(%)`、`累計營業收入-當月累計營收`（千元）。

## 分析流程（使用者問某檔股票時）

1. 確認代號、上市或上櫃、所屬產業，找 2～4 家同業。
2. 有本機資料庫就先 `latest --code` 取最新行情、估值、月營收；沒有就請使用者提供或說明查不到。
3. 依 `references/tw_market_notes.md` 檢查台股特有項目：月營收趨勢（年增率、累計年增率、季節性）、
   現金股利與配發率、董監持股與質押、三大法人與融資融券（若有資料）、處置／注意股。
4. 輸出：一段結論 → 同業比較表（標單位與日期）→ 風險與資料缺口 → 資料來源清單 → 非投資建議聲明。
