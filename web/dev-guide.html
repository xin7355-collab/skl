App 開發全流程

從想法、雛形、GitHub、Claude Code 到上線（網頁 App／Android／iOS）：技能什麼時候用、要花多少錢、要注意什麼。

先回答：「聊天 AI 做雛形 → 匯出 → 帶到 Code → 上架 GitHub」對嗎？

大方向對，但有三個地方要調整：

  1. 雛形可做可不做。在 Claude App 請它做「手機尺寸的單一 HTML 可點擊雛形」，聊天畫面裡就能直接看、改到滿意。 不用自己匯出整個專案，只要下載或複製那一個 HTML 檔，到 Claude Code 上傳，說「照這份做出來」。
  2. 先建 GitHub repo，再開 Claude Code。雲端的 Claude Code 是「在你的 repo 裡面工作」：改程式、測試、合併、推上去都在裡面完成，不用你搬檔案。
  3. GitHub 不是商店。GitHub 是放程式碼、免費架網站（Pages）、免費排程（Actions）的地方。 網頁 App 在 GitHub Pages 上線後，iPhone 用 Safari「加入主畫面」就能像 App 一樣用。 要進 App Store／Google Play 才叫「上架」，那要另外付費、送審。
最推薦的路線：先做網頁 App（PWA），免費、不用電腦、改了馬上更新；真的需要商店再包裝上架（見「平台」）。
0想清楚要做什麼（5 分鐘）手機備忘錄就好
  • 給誰用（自己、家人朋友、公開）、解決什麼問題。
  • 最重要的 3 個功能就好，其他之後再加。功能越少越快做完。
  • 資料從哪來：自己輸入、官方 API（例如證交所 OpenAPI）、還是要抓別人的網頁。
  • 要不要登入、要不要 AI、要不要收錢——這三個會決定費用和風險。

不知道怎麼寫？到「起手式」分頁勾一勾，會幫你產生要貼給 AI 的指令。

1跟聊天 AI 討論，產出一頁規格Claude App（手機）
  • 貼上「起手式」分頁產生的 A 段：它會先問你幾個問題，再寫出規格（功能、畫面、資料來源、平台建議、費用與風險）。
  • 想參考別人做好的：用 Repo X-Ray 搜尋 GitHub 上類似的開源專案，看授權、按「🧩 參考它做我的 App」。
技能

這一步還用不到 skl 技能：技能是裝在 repo 裡、給 Claude Code 用的（第 4 步才裝）。

2做雛形（可略過）Claude App
  • 請它做「手機尺寸、單一 HTML、假資料」的可點擊雛形，在聊天畫面直接看、一直改到滿意。
  • 滿意後下載那個 HTML 檔（或複製全部程式碼），第 5 步會用到。
雛形只確認「長怎樣、怎麼點」。資料是假的，不要放任何真的金鑰或個資。
3建 GitHub repo手機瀏覽器 github.com/new
  • 取英文名字，選 Public（公開），勾「Add a README file」。
  • 為什麼選公開：公開 repo 用標準 runner 跑 Actions 免費而且不限量（含 macOS）；免費帳號的 GitHub Pages 也只能用公開 repo。 GitHub GitHub
  • 建好後，把 repo 加進 skl 的 .github/apps.json（請 skl 的 Claude 幫你加），Repo X-Ray「我的 App」和每週健檢才看得到它。
公開 repo 的程式碼、commit 紀錄、Issue 任何人都看得到：金鑰放 Settings → Secrets，不想公開的資料（工作單位、個資）不要放進 repo。
4第一次開 Claude Code：裝技能＋工作守則claude.ai/code 或 Claude App 技能從這裡開始介入
  • 開 claude.ai/code（Claude 手機 App 也能操作雲端工作階段），選剛建好的 repo。 雲端工作階段需要 Pro 以上方案。Claude
  • 貼上「起手式」分頁的 B 段（或技能庫網頁「組合安裝」的指令）： 它會把技能裝進 repo 的 .claude/skills/、建立 CLAUDE.md 工作守則，裝完會先列執行方案，再直接接著做。
技能怎麼運作
  • 裝在 repo 裡的技能，之後每次開工作階段都會自動載入，你不用記技能名稱。
  • Claude 會依你的要求自動挑用：說「修 bug」→ systematic-debugging； 說「畫面變好看」→ design-taste-frontend；上傳檔案說「做出來」→ file-intake。
  • 技能需要的套件（npm／pip、Chrome、ffmpeg）會寫進 repo 的設定檔。雲端工作階段每次都是新的容器，只裝在容器裡的東西下次就不見了。
5把雛形做成真的 AppClaude Code
  • 上傳雛形 HTML（或貼第 1 步的規格），說「照這份做出來」。
  • Claude 會先列計畫、做出來、用 Playwright 在 iPhone 尺寸驗證，再合併推上去。

6上線成網頁 App（PWA）GitHub Pages（自動） 免費
  • 由 GitHub Actions 工作流部署到 GitHub Pages，網址像 https://帳號.github.io/repo名稱/。
  • 要能「安裝」：網址要是 HTTPS（GitHub Pages 就是），manifest 要有 name（或 short_name）、 192px 與 512px 圖示、start_url、display。 MDN
  • iPhone：用 Safari 打開網址 → 分享 → 加入主畫面。
  • GitHub Pages 的限制：網站最大 1GB、每月流量軟上限 100GB、不能拿來經營網路商店。 GitHub

7加資料、AI、自動化Claude Code＋GitHub Actions
  • 資料自動更新：GitHub Actions 排程（例如每天 06:00 抓台股官方 OpenAPI，存成 JSON 給網頁讀）。技能 tw-stockweb-to-markdown。
  • 用 AI：金鑰放 GitHub Secrets；在 Actions 或 Cloudflare Worker 裡呼叫，網頁裡不能有金鑰（網頁程式碼任何人都看得到）。 模型名稱不寫死，用 ai-model-router。一定要在 AI 服務商後台設每月預算上限。
  • 需要藏金鑰的 API：Cloudflare Workers 免費方案每天 10 萬次請求，夠個人 App 用。 Cloudflare

建議：先做網頁 App。等每天都在用、功能穩定，真的需要商店時再包裝上架——同一份程式碼可以沿用。

Android：把網頁 App 上架到 Google Play

  1. 先把 PWA 做好（manifest、圖示、HTTPS）。
  2. 用 PWABuilder 包成 Android 專案（它底下用 Google 的 Bubblewrap，做出「Trusted Web Activity」：全螢幕打開你的網站、沒有網址列）。 PWABuilder※ Chrome※
  3. 在網站放 /.well-known/assetlinks.json 證明網站是你的（Digital Asset Links）；驗證失敗時會退回成有網址列的瀏覽器分頁。 Chrome※
  4. 註冊 Play Console（US$25 一次），上傳 → 封閉測試 12 人連續 14 天 → 申請正式上架。
  5. 2026/8/31 起，新 App 和更新都要 target Android 16（API 36）以上。 Android
開發者身分驗證（2026–2027）

2026/9/30 起，先在巴西、印尼、新加坡、泰國，從參與的商店安裝 App 時會檢查開發者有沒有驗證身分；2027 年擴大到全球的認證裝置。 Google Play 上 99% 的 App 已自動登記。只給自己和少數人用，可以用免費的「limited distribution」，最多分享給 20 台裝置、不用身分驗證。 Android Android

iOS：上架到 App Store

  1. 選做法：Capacitor（沿用網頁 App 的程式碼包成 iOS App）或 Expo（React Native，一份程式碼出 iOS 和 Android）。 Capacitor 自己建置 iOS 要 macOS＋Xcode。Capacitor
  2. 沒有 Mac 就用雲端建置：Expo 的 iOS 建置跑在 Expo 的 macOS 雲端，也能幫你管簽章憑證 Expo； Codemagic 個人帳號每月 500 分鐘 macOS M2 免費 Codemagic※； GitHub Actions 公開 repo 的 macOS runner 也免費 GitHub。
  3. 加入 Apple Developer Program（US$99／年，報名時以當地貨幣顯示）。免費的 Apple 帳號只能用 Xcode 裝到自己的裝置測試（最多 3 台、7 天後失效，而且要有 Mac），不能用 TestFlight、不能上架。 Apple Apple
  4. 上傳到 App Store Connect（要用 Xcode 26 以上建置）Apple → TestFlight 測試（內部最多 100 人、外部最多 10,000 人，每個測試版本可測 90 天） Apple Apple → 送審。
最常被退件的原因
  • 規則 4.2：「App 要有功能、內容和介面，超越重新包裝的網站」。只把網站包一層很容易被退，要加 App 才有的價值（推播、離線、小工具、相機等）。
  • 規則 5.1.1：一定要有隱私權政策連結；App 能註冊帳號，就必須能在 App 裡刪除帳號。

金鑰與隱私

  • 金鑰絕對不放網頁程式碼裡：網頁 App 的程式碼任何人都看得到。放 GitHub Secrets，讓 Actions 或 Cloudflare Worker 使用。
  • 公開 repo 的程式碼、commit 紀錄、Issue 全部公開；工作單位、個資等不想公開的東西不要 commit。網站加 noindex，不讓搜尋引擎收錄。
  • GitHub Pages 不能拿來經營網路商店，也不要用來傳送密碼或信用卡號。 GitHub
  • 上架 App Store 的個人帳號，本名會公開顯示為賣家；不想公開本名要用公司（組織）帳號。 Apple

iPhone 網頁 App 的眉角

  • Safari 對沒在用的網站，會在 7 天後清掉它存在手機裡的資料；加到主畫面的 App 另外計算，只算你實際打開的天數。 重要資料不要只存在手機，要能同步到雲端或匯出。 WebKit※
  • 推播：iOS 16.4 起支援，但要先加到主畫面，而且要使用者按按鈕才能請求通知權限；不需要 Apple 開發者會員。 WebKit※
  • 安裝：iPhone 要從 Safari 的分享選單手動「加入主畫面」，把這一步寫在 App 的說明裡。
經驗提醒（沒有附官方出處，是開發時常踩的坑）
  • 輸入框字小於 16px，iPhone 點下去會自動放大畫面。
  • 瀏海和底部橫條：用 viewport-fit=cover 加 env(safe-area-inset-*) 留空間。
  • 改版後手機一直看到舊版：要有版本號機制，讓 App 自己發現新版就重新載入。
  • 一定要在自己的 iPhone 上實際點一遍，模擬器看起來沒問題不代表真機沒問題。

上架審核

  • App Store 規則 4.2：只把網站包一層會被退件。Apple
  • 有註冊功能就要能在 App 裡刪除帳號；要有隱私權政策連結（App 內和 App Store Connect 都要放）。
  • Google Play 新的個人帳號：正式上架前要先封閉測試 12 人、連續 14 天，中途退出的不算。 Google※
  • 審核要時間，不要等到最後一天才送。

法規（台灣）

  • 個資：向別人蒐集個資（姓名、電話、Email）時，要告知蒐集者是誰、目的、資料類別、利用期間與方式、當事人的權利、不提供的影響。 個資法第 8 條※
  • 股票類 App：法律定義的「證券投資顧問」，是「取得報酬」並對有價證券提供分析意見或推介建議；未經許可經營，可處 5 年以下有期徒刑， 併科新臺幣 100 萬元以上 5,000 萬元以下罰金。自己用沒問題；要收費提供個股建議給別人，先找專業確認。 投顧法第 4 條※ 第 107 條※
  • 資料來源：抓別人網站的資料要看對方的使用規範；有官方 API 就用 API。

以上是一般資訊、不是法律意見。
