三個原則（整份教學都照這個做）

  1. 你是產品負責人和測試者，Claude 是工程師：你說要什麼、在手機上試；它寫程式、跑測試。
  2. 一次只做一件事：一個功能做完、驗證、上線，再做下一個。出錯時才知道是哪一步。
  3. 描述現象，不要猜原因：截圖＋「我按了什麼、看到什麼、希望看到什麼」，比「好像是資料庫壞了」有用。

照著做的教學

每一步都有：🎯 目標、📍 在哪裡、👆 怎麼做、📋 要貼的、👀 會看到、✅ 完成標準、🆘 卡住怎麼辦。做完按最下面的「這一步做完了」。

1想清楚要做什麼手機備忘錄 5 分鐘
🎯 目標
用三句話說清楚：給誰用、解決什麼問題、最重要的 3 個功能。
👆 怎麼做
  1. 寫下：「我想做一個 ＿＿，給 ＿＿ 用，因為 ＿＿。」
  2. 列出想要的功能，只留最重要的 3 個，其他寫在「之後再做」。
  3. 想一下資料從哪來：自己輸入、官方 API（例如證交所 OpenAPI）、還是別人的網站。
  4. 要不要登入、要不要 AI、要不要收錢——這三個決定費用和風險。
📋 不知道寫什麼
到 範例 挑一個像的，或到 起手式 一題一題回答。
✅ 完成標準
三句話寫得出來；核心功能不超過 3 個。
🆘 卡住怎麼辦
想做的東西太多
先做「最小可用版本」：只留每天一定會用的那 1～3 個功能。做出來用一週，再決定下一個要加什麼。
不確定需不需要做成 App
只是定期整理資料、做報告，用 Claude App 的「交辦工作」或排程任務就夠，不用做 App。看 AI Agent 製作流程。
2跟 Claude App 討論出規格Claude App 10–20 分鐘
🎯 目標
拿到一頁規格：核心功能、畫面清單、資料從哪來、平台建議、可能的費用與風險。
📍 在哪裡
iPhone 的 Claude App → 開新對話。
👆 怎麼做
  1. 到 起手式 回答問題（或套用範例），複製 A 段。
  2. 在 Claude App 開新對話，貼上、送出。
  3. Claude 會先問你最多 5 個問題，照實回答；不確定就說「用你的建議」。
  4. 拿到規格後，檢查核心功能有沒有超過 3 個；太多就說「砍到最重要的 3 個」。
📋 沒用起手式時可以貼這段
我想做一個 App：（寫你的三句話）

請你：
1. 先一次問我最多 5 個問題，把需求問清楚，等我回答再繼續。

3. 每個核心功能寫成「使用者可以＿＿」的勾選清單，之後當完成標準。
👀 會看到
Claude 先問問題，接著給一頁條列的規格。
✅ 完成標準
規格裡有：3 個以內的核心功能（每個都有勾選清單）、每個畫面的名字、資料從哪來、平台建議、可能的費用。
🆘 卡住怎麼辦
Claude 沒問問題就直接寫程式
回它：「先不要寫程式，先問我問題，等我回答。」
規格太長看不懂
說：「用 10 行以內、國中生看得懂的話重寫。」
不知道要做網頁還是 iPhone App
先做網頁 App（PWA）：免費、不用電腦、改了馬上更新。真的需要商店再上架，同一份程式可以沿用。比較見 比較。
🧩 技能
這一步還用不到 skl 技能：技能是裝在 repo 裡、給 Claude Code 用的（第 5 步才裝）。
3做可以點的雛形（可略過）Claude App 先看畫面再開工
🎯 目標
在手機上點點看畫面長怎樣，確定了再開工，比做完才改省很多時間。
👆 怎麼做
  1. 在第 2 步同一個對話貼下面這段。
  2. 對話裡會出現可以點的預覽，點每個按鈕試試看。

✅ 完成標準
每個主要畫面都點過，你覺得「就是這樣」。

預覽是空白的

4建 GitHub repoSafari github.com/new
🎯 目標
有一個放程式碼的地方。網站、排程、資料之後都在這裡。
👆 怎麼做
  1. Safari 打開 github.com/new（要先登入 GitHub）。
  2. Repository name：英文小寫、短，例如 family-budget。
  3. 選 Public（公開），打開「Add README」。
  4. 按 Create repository，記下網址 https://github.com/你的帳號/名稱。
為什麼選公開
公開 repo 用標準 runner 跑 Actions 免費不限量（含 macOS）；免費帳號的 GitHub Pages 也只能用公開 repo。 GitHub GitHub
公開代表程式碼、commit 紀錄、Issue 任何人都看得到：金鑰放 Settings → Secrets，工作單位、個資等不想公開的東西不要放進 repo。
👀 會看到
repo 頁面，裡面有一個 README.md。
✅ 完成標準
網址打得開，右上角顯示 Public。
🆘 卡住怎麼辦
名稱被用過了
同一個帳號底下不能重名，換一個就好（例如加上 -app）。
手機版畫面找不到某個設定
Safari 網址列的選單選「要求桌面版網站」，GitHub 會顯示完整選單。
想讓 skl 每週幫這個 App 健檢
到 skl 的 Claude Code 說：「把 你的帳號/名稱 加進 .github/apps.json」。Repo X-Ray 的「我的 App」也會出現它。

7開 GitHub Pages、加到主畫面GitHub 設定Safari 免費
🎯 目標
手機主畫面有你的 App 圖示，點開是全螢幕，像一般 App。
👆 怎麼做
  1. 打開 https://github.com/你的帳號/名稱/settings/pages（repo 的 Settings → Pages）。
  2. Build and deployment 底下的 Source 選 GitHub Actions。 GitHub
  3. 到 repo 的 Actions 分頁，等部署那一列變綠色勾勾（1–3 分鐘）。
  4. Safari 打開 https://你的帳號.github.io/名稱/。
  5. 分享選單 → 加入主畫面。
要能「安裝」的條件
網址要是 HTTPS（GitHub Pages 就是），manifest 要有 name（或 short_name）、192px 與 512px 圖示、start_url、display。 MDN
👀 會看到
主畫面出現圖示；點開沒有網址列。
✅ 完成標準
從主畫面打開，核心功能都能用；關掉再開，資料還在。
🆘 卡住怎麼辦
打開是 404
三種可能：Pages 還沒開（回第 2 點）、部署還沒跑完（看 Actions）、網址大小寫打錯（repo 名稱要一模一樣）。私人 repo 在免費帳號不能用 Pages。
一直看到舊版
從多工畫面把 App 往上滑掉再打開。常常發生的話，請 Claude「加版本號檢查，有新版自動重新載入」。
畫面一片白
截圖給 Claude：「從主畫面打開是白的，Safari 直接開正常／也是白的」。讓它用 Playwright 重現。
找不到「加入主畫面」
建議用 Safari 打開；在分享選單往下滑，或點「編輯動作」把它加回來。
限制
GitHub Pages 網站最大 1GB、每月流量軟上限 100GB、不能拿來經營網路商店或傳送密碼、信用卡號。 GitHub

10上架 Google Play（選擇）PWABuilderPlay Console US$25 一次
🎯 目標
把網頁 App 包成 Android App 上架。
👆 怎麼做
  1. 先把 PWA 做穩（manifest、圖示、HTTPS）。
  2. 用 PWABuilder 包成 Android 專案（Trusted Web Activity：全螢幕打開你的網站、沒有網址列）。 Chrome※
  3. 在網站根目錄放 /.well-known/assetlinks.json 證明網站是你的；驗證失敗會退回成有網址列的瀏覽器。 Chrome※
  4. 註冊 Play Console（US$25 一次）→ 上傳 → 封閉測試 12 人連續 14 天（2023/11/13 之後開的個人帳號）→ 申請正式上架。 Google※
  5. 2026/8/31 起，新 App 和更新都要 target Android 16（API 36）以上。 Android
GitHub Pages 的坑：assetlinks.json 要放在網址的最上層（例如 https://你的帳號.github.io/.well-known/），專案網址 你的帳號.github.io/名稱/ 底下放無效，要另開一個「你的帳號.github.io」repo 或用自己的網域。
🆘 卡住怎麼辦
App 打開上面有網址列
assetlinks 驗證失敗：檔案位置不對、指紋（SHA-256）不對、或網址有轉址。請 Claude 對照 PWABuilder 給的指紋檢查。
找不到 12 位測試者
家人朋友都算，要用 Android 手機加入測試並連續保持 14 天。只給自己少數人用，可以考慮不上架、直接用網頁 App。

完整案例：從零到上線

照著做就能做出來。每一步寫了你要做什麼、要貼的話、會看到什麼。

📈 案例一：台股觀察清單（每天自動更新）難度 ★★☆　費用 0 元（只要 Claude 訂閱）　約半天

做出來長怎樣：手機打開就看到自選的 10 檔股票收盤價、漲跌、本益比；每天收盤後自動更新，失敗會開一則只寫數量的 Issue 通知你。

為什麼這樣設計：資料由 GitHub Actions 排程抓證交所官方 OpenAPI、存成 JSON，網頁只讀 JSON——不用伺服器、不用金鑰、不怕網頁被看到原始碼。你的 StockAI-DB 就是這個架構的進階版。

1. 起手式到 起手式 的範例套用「台股觀察清單」，把 A 段的股票代號改成你的。
2. Claude App 討論規格貼 A 段。它問「要看哪些欄位」時，回「收盤價、漲跌、本益比、殖利率」。
👀 拿到 3 個核心功能：清單、單檔明細、每日更新。
3. 建 repo名稱 tw-watchlist、Public。
4. Claude Code貼 B 段（組合 core,pwa,actions,stock）。
👀 它會用 tw-stock 技能，建排程工作流，並告訴你排程時間換算成 UTC。
5. 做第一版貼： 
照規格做第一版：自選清單先放 2330、2317、2454 三檔（之後在畫面上可以改）。
資料用 tw-stock 抓上市每日行情和本益比，GitHub Actions 每個交易日 15:40（台灣時間）跑，存成 data/latest.json。
網頁顯示資料日期；抓失敗不要覆蓋舊資料，開 Issue 通知我（標題和內文只寫數量）。
6. 開 Pages、加到主畫面見 第 7 步。
✅ 隔天收盤後打開，資料日期變成今天。
7. 之後可以加到價提醒（LINE）、每週 AI 整理（AI Agent）。給別人看時不要寫成買賣建議（見「注意」的投顧法）。
💰 案例二：家庭記帳本（資料只在手機，可匯出）難度 ★☆☆　費用 0 元　約 2–3 小時

做出來長怎樣：打開就能記一筆（金額、類別、備註），每月圓餅圖，可以匯出 CSV 用 Excel 打開，沒網路也能用。

為什麼這樣設計：資料存在手機（IndexedDB），不用登入、不用雲端、沒有個資外洩的風險；代價是換手機要靠匯出／匯入搬資料。

1. 起手式套用範例「家庭記帳本」。
2. 規格貼 A 段。重點確認：類別有哪些、要不要多人記帳（要的話就不能只存手機，會變成案例三那種有雲端的難度）。
3. 建 repo → 4. 貼 B 段（組合 core,pwa,visual）。
5. 做第一版貼： 
照規格做第一版：記一筆、本月清單、每月各類別圓餅圖。
資料存 IndexedDB；做「匯出 CSV」（Excel 打開不能是亂碼）和「匯入」；要能離線使用（service worker）。
測試要包含：記一筆後重新整理還在、匯出再匯入資料一樣。
6. 上線加到主畫面後，關掉網路試記一筆。
✅ 開飛航模式也能記帳、匯出的 CSV 在 Excel 打開正常。
7. 記得每個月匯出一次備份：Safari 對很久沒開的網站會清資料（見「注意」）。
🛒 案例三：降價提醒＋LINE 通知難度 ★★☆　費用 0 元（LINE 免費方案每月 200 則）　約一天

做出來長怎樣：把想買的商品網址加進清單，每天自動查價，降到你設的價格就用 LINE 傳訊息給你；網頁看每個商品的價格走勢。

為什麼這樣設計：你的 PriceHub（比價通） 就是這樣做的：Actions 排程採集、限流＋指數退避、價格存在獨立的 data 分支、網站放 gh-pages，零伺服器成本。

1. 先確認資料來源只抓允許抓的網站：先看網站的使用規範和 robots.txt，有官方 API 就用 API。
2. 起手式套用範例「降價提醒」，通知選 LINE。
3. LINE 準備建 LINE 官方帳號、開 Messaging API，拿到 Channel access token（Claude 會一步一步教你，token 只貼到 GitHub Secrets，不要貼進對話）。
4. 做第一版貼： 
照規格做第一版：watchlist.json 放商品網址和目標價。
GitHub Actions 每天 09:10（台灣時間）查價，價格歷史存 data 分支（不要讓 main 的歷史變大）。
抓取要限流、失敗用指數退避重試，遵守 robots.txt；某個網站抓不到要列出是哪幾個，不能默默給空資料。
降到目標價就用 LINE Messaging API push 給我，token 讀 secrets.LINE_TOKEN；每月則數快用完時提醒我。
5. 驗收把一個商品的目標價設得比現價高，手動執行工作流一次。
✅ LINE 收到通知、網頁看到價格點。

金鑰與隱私

  • 金鑰絕對不放網頁程式碼裡：網頁 App 的程式碼任何人都看得到。放 GitHub Secrets，讓 Actions 或 Cloudflare Worker 使用。
  • 公開 repo 的程式碼、commit 紀錄、Issue 全部公開；工作單位、個資等不想公開的東西不要 commit。網站加 noindex，不讓搜尋引擎收錄。
  • GitHub Pages 不能拿來經營網路商店，也不要用來傳送密碼或信用卡號。 GitHub
  • 上架 App Store 的個人帳號，本名會公開顯示為賣家；不想公開本名要用公司（組織）帳號。 Apple

iPhone 網頁 App 的眉角

  • Safari 對沒在用的網站，會在 7 天後清掉它存在手機裡的資料；加到主畫面的 App 另外計算，只算你實際打開的天數。重要資料不要只存在手機，要能同步到雲端或匯出。 WebKit※
  • 推播：iOS 16.4 起支援加到主畫面的網頁 App，要使用者按按鈕才能請求通知權限；不需要 Apple 開發者會員。 Apple
  • 安裝：iPhone 要從分享選單手動「加入主畫面」，把這一步寫在 App 的說明裡。
經驗提醒（沒有附官方出處，是開發時常踩的坑）
  • 輸入框字小於 16px，iPhone 點下去會自動放大畫面。
  • 瀏海和底部橫條：用 viewport-fit=cover 加 env(safe-area-inset-*) 留空間。
  • 改版後手機一直看到舊版：要有版本號機制，讓 App 自己發現新版就重新載入。
  • 一定要在自己的 iPhone 上實際點一遍，模擬器看起來沒問題不代表真機沒問題。

功能的眉角（起手式的選項會用到）

  • 推播：加到主畫面的網頁 App 在 iOS 16.4 以上可以收推播，不用加入 Apple 開發者計畫；要讓使用者按按鈕才能請求權限。 Apple
  • LINE：LINE Notify 已在 2025/3/31 停止服務，要改用官方帳號的 Messaging API LINE※。 免費的輕用量方案每月 200 則，只有群發和主動推播（Push）算則數，回覆使用者的訊息不算 LINE※； 2026/11/1 起中用量、高用量月費調漲，輕用量維持免費 200 則 LINE※。
  • Telegram：機器人對使用者和開發者都免費 Telegram※； 呼叫 Bot API 時 token 一定在網址裡（官方格式），錯誤訊息和 log 不能印出完整網址 Telegram※。
  • iPhone 捷徑：「取得 URL 內容」動作可以呼叫 API（GET、POST 等），做成一鍵執行或放進分享選單。 Apple※
  • 相機與定位：網頁要 HTTPS（GitHub Pages 就是）並經使用者同意。 MDN MDN Safari 的條碼辨識 API 預設沒開，iPhone 掃碼要用 JavaScript 函式庫。 MDN
  • 語音：Safari 的語音辨識要用 webkit 開頭的版本（webkitSpeechRecognition），朗讀（語音合成）可以直接用。 MDN
  • 地圖：OpenStreetMap 的公用圖磚不能大量使用、不能預先下載或離線使用，用量大要換服務或自己架。 OSM※
  • 政府開放資料：依授權條款，使用時要標示提供機關（沒標示等於沒取得授權）。 政府資料開放平臺※
  • 按鈕大小：iPhone 按鈕預設 44×44 點、最小 28×28 點；給長輩用就照 44。 Apple

MDN 的支援情況是用 MDN 公開的瀏覽器相容性資料（GitHub 上的原始資料）核對的。

技術說明（看懂 Claude 在做什麼）

不用會寫，但知道這些，才看得懂 Claude 的方案、知道該問什麼。每段最後是「可以跟 Claude 說的話」。

1. 網頁 App（PWA）由什麼組成

  • index.html：畫面和程式本體。小 App 一個檔案就夠，比較好維護。
  • manifest.json：App 名稱、圖示、打開時全螢幕。少了它就不能「安裝」。 MDN
  • service worker：在背景幫網頁存檔案，讓沒網路也能打開；也是「看到舊版」最常見的原因，所以要有版本號機制。
  • version.json＋版本檢查：App 切回前景時比對版本，不同就重新載入（skl 的網頁就是這樣做）。

可以說：「用最簡單的 PWA 結構：單一 index.html、manifest、service worker，加版本檢查，有新版自動重新載入。」

2. 資料存在哪

  • localStorage：存少量設定（例如上次選的分頁）。
  • IndexedDB：存比較多的資料（記帳紀錄、筆記）。兩者都只在這支手機的這個瀏覽器裡，會被 Safari 清掉（見「注意」）。
  • repo 裡的 JSON：Actions 排程寫入、網頁讀取，適合公開資料。
  • 雲端資料庫（Supabase、Cloudflare D1…）：多裝置、多人共用才需要；要處理登入、權限、個資。

可以說：「資料先存 IndexedDB，做匯出／匯入 JSON；之後要同步再加雲端。」

3. 排程（GitHub Actions）怎麼運作

  • 工作流檔放在 .github/workflows/，用 cron 寫時間；預設是 UTC（台灣時間減 8 小時），也可以指定時區。最短每 5 分鐘一次。
  • 只會在預設分支（main）跑；尖峰（整點）可能延遲，嚴重時排隊中的工作會被丟掉，所以選非整點時間。
  • 公開 repo 60 天沒有活動會自動停用排程。

GitHub GitHub

可以說：「排程用 Asia/Taipei 時區、避開整點；失敗不要覆蓋舊資料，開 Issue 通知我（只寫數量）。」

4. 金鑰怎麼藏：Worker 代理

網頁 → 你的 Cloudflare Worker（金鑰存在 Worker 的 Secrets）→ 外部 API。網頁只知道 Worker 的網址，看不到金鑰；Worker 還能限制次數，避免被別人拿去刷。 免費方案每天 10 萬次請求。Cloudflare

可以說：「外部 API 透過 Cloudflare Worker 轉，金鑰放 Worker Secrets，用 HTTP 標頭傳；每個 IP 每分鐘最多 N 次。」

5. 三個分支的資料流（你的 StockAI-DB、PriceHub 都這樣做）

  • main：程式碼，你和 Claude 改這裡。
  • data：排程抓到的資料，每次覆蓋成一個 commit，repo 不會越長越大。
  • gh-pages：網站成品（程式＋最新資料），由工作流產生。

6. 測試：Claude 怎麼知道自己做對了

  • 自我測試（selftest）：不連網就能跑的檢查，抓資料的程式也要能用假資料測。
  • Playwright E2E：在雲端開瀏覽器、用 iPhone 尺寸點你的 App，確認按鈕、資料真的對。
  • CI：每次推上去自動跑測試，紅燈就不部署。

可以說：「每個核心功能都要有 Playwright 測試，推上去前全部跑過；告訴我驗過什麼、沒驗到什麼。」

7. 安全的基本功

  • 外部來的文字（網址、使用者輸入、抓來的網頁）顯示時當純文字，不當 HTML，避免被塞程式碼。
  • 只收需要的個資；log 和錯誤訊息不印金鑰與個資。
  • 第三方套件固定版本，定期跑漏洞檢查（dependency-auditor）。
