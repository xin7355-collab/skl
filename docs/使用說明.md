# skl 使用說明

## 這個 repo 是什麼

1. **技能庫本體**：從開源專案 claude-skills（MIT 授權）整包匯入，約 388 個技能，
   涵蓋工程、產品、行銷、財務、法遵等，各自是 `SKILL.md` + 純標準函式庫 Python 工具。
   上游原始說明在 [upstream/README.md](upstream/README.md)。
2. **自製外掛 `xin-toolkit/`**（外掛名 `xin-app-toolkit`）：讓你的**其他 App** 用得到這些技能。
   - `app-guardrails-audit`：依低資源防禦準則掃描專案（見下方規則表）。
   - `app-bootstrap`：把挑好的技能組合＋CLAUDE.md 工作守則一鍵複製進其他 App 的 repo。

## 匯入時做了哪些修改（以及為什麼）

| 修改 | 原因 |
|---|---|
| 刪掉 `.claude/settings.json` | 上游設定會在每次工作階段**自動載入第三方外掛**（別人的 GitHub repo），等於把程式執行權交給陌生人 |
| 刪掉 `.mcp.json` | 要求本機安裝 `tessl` 指令，沒裝的話每次開工作階段都會噴 MCP 錯誤 |
| 刪掉 11 個上游工作流，只留 `CI Quality Gate` | 那些需要上游作者的金鑰（`CLAUDE_CODE_OAUTH_TOKEN`、`VT_API_KEY`、`PROJECTS_TOKEN`），或會發上游版本 Release、部署上游文件站；在你的 repo 只會紅燈 |
| CI 改成 push 到 main 就跑，加跑兩支工具的自我測試 | 你不走 PR，原本只在 PR 觸發就等於從來不跑 |
| CI 移除「計數器檢查」與「README 連結檢查」 | 這兩項是檢查上游 README 的行銷數字；README 已依你的守則精簡 |
| 上游 `README.md`、`CLAUDE.md` 搬到 `docs/upstream/` | README 要精簡（公開 repo）；上游 CLAUDE.md 有 110 KB，放根目錄會在**每次工作階段**吃掉大量上下文 |
| 根目錄 `CLAUDE.md` 換成你的工作守則（第 6 節 PWA 章節拿掉、填好本專案資訊） | 這個 repo 不是 PWA；PWA 章節保留在給其他 App 的範本裡 |
| 刪掉上游的 Google 網站驗證檔、贊助設定、議題範本、分支保護設定 | 都是上游作者帳號專用 |

## 技能挑選網頁

https://xin7355-collab.github.io/skl/ （可在 Safari「分享 → 加入主畫面」）

- 「組合安裝」：勾選組合 → 複製給 Claude 的指令 → 貼到其他 App 的 Claude Code 對話。
- 「瀏覽技能」：全部技能的中文說明，可搜尋、依「類別」（用途，例如股票投資、資安）或
  「來源領域」（上游資料夾）篩選；單個複製或勾選多個一次複製。
  分類規則在 `web/categories.json`，分錯的技能在 `overrides` 指定即可。
- 「健檢更新」：複製健檢指令、更新指令。
- 每次推送到 main 會自動重新部署；手機上的舊頁面切回前景時偵測到新版會自動重載。

**為什麼技能本體不翻成中文**：Claude 讀英文指令最精準，技能裡有大量指令、程式與專有名詞，
翻譯容易改壞；也會讓日後同步上游變得不可能。回覆語言由各 App 的 CLAUDE.md 決定，所以
英文技能照樣產生中文回答。中文只放在網頁顯示層（`web/zh.json`），不影響技能效果。

## 讓其他 App 用這些技能（推薦做法）

在**那個 App 的** Claude Code 工作階段裡，直接跟 Claude 說：

> 從 https://github.com/xin7355-collab/skl 用 app-bootstrap 幫這個 repo 裝技能，組合你幫我判斷，裝完跑一次 guardrails 健檢。

Claude 會照 `xin-toolkit/skills/app-bootstrap/SKILL.md` 的流程做。想自己下指令的話：

```bash
git clone --depth 1 https://github.com/xin7355-collab/skl /tmp/skl
python3 /tmp/skl/xin-toolkit/skills/app-bootstrap/scripts/bootstrap_app.py list
python3 /tmp/skl/xin-toolkit/skills/app-bootstrap/scripts/bootstrap_app.py install --target . --packs core,pwa,actions
```

**技能組合**（在 `xin-toolkit/skills/app-bootstrap/assets/packs.json` 增減）：

| 組合 | 內容 | 什麼時候選 |
|---|---|---|
| core | 架構審查、程式碼審查、精準修 bug、上線前檢查、套件漏洞 | 一律 |
| pwa | 前端、Playwright 瀏覽器自動化、效能分析 | 手機網頁／PWA |
| actions | CI/CD、DevOps、金鑰管理 | 有 GitHub Actions |
| backend | 後端、SQL／SQLite、API 設計審查 | 有資料庫或 API |
| security | 資安審查、第三方技能安全掃描 | 有登入、金鑰、使用者資料 |
| stock | 台股資料收集與分析（tw-stock）、美股／印度股基本面、財報與估值 | 股票相關 App 或要分析個股 |

### 台股（tw-stock）

- 資料來源：證交所、櫃買中心官方 OpenAPI（免金鑰）——上市／上櫃每日行情、本益比／殖利率／淨值比、
  上市月營收、上市公司基本資料。**官方只給最新快照**，歷史要每天排程自己存。
- 其他 App 要每天收集：把 `xin-toolkit/skills/tw-stock/assets/tw-stock-daily.yml` 放進該 App 的
  `.github/workflows/`，交易日 15:30 自動抓，資料庫存在 Release 附件（不進 git）。
- 內建限流與指數退避，避免被證交所封鎖 IP；分析時一律附資料出處，不提供買賣建議。
- 注意：公開 repo 的 Release 附件任何人都能下載；官方資料的轉載規範請自行確認。

`app-guardrails-audit` 每次都會一起裝。全部組合一起裝約 2 MB。

**為什麼是「複製」而不是「外掛市集」**：Claude Code 支援在專案的 `.claude/settings.json`
用 `extraKnownMarketplaces` + `enabledPlugins` 指定外掛，但官方文件寫明「來自外部 GitHub
的外掛要使用者先安裝一次才會載入」，雲端／手機工作階段不保證自動完成。repo 裡的
`.claude/skills/` 則是每次都一定會載入。你用 iPhone，複製最不會出意外。

**更新**：技能庫改版後，在該 App 重跑 `bootstrap_app.py update --target .`。
只更新當初由這支工具裝的技能，不會碰你自己寫的技能或 CLAUDE.md。

**有電腦時的另一條路**（選用）：在 Claude Code 輸入
`/plugin marketplace add xin7355-collab/skl`，再 `/plugin install xin-app-toolkit@claude-code-skills`。

## 防禦掃描規則

```bash
python3 .claude/skills/app-guardrails-audit/scripts/guardrails_audit.py audit .
```

| 規則 | 等級 | 對應守則 |
|---|---|---|
| secret-in-url／hardcoded-secret／log-secret | 🔴／🔴／🟡 | 金鑰走標頭、不印出、不 commit |
| ios-share-title | 🔴 | iPhone 分享檔案不帶 title |
| file-to-arraybuffer | 🟡 | 大檔不先讀成 ArrayBuffer |
| unbounded-promise-all／unbounded-gather | 🟡 | 前端請求要佇列限流 |
| http-no-retry | 🔵 | 外部請求要指數退避重試 |
| sqlite-no-wal／sqlite-no-timeout | 🟡 | SQLite 維持 WAL、防鎖死 |
| pandas-no-chunks | 🔵 | 1GB RAM 主機要分批 |
| hardcoded-model | 🟡 | 不寫死模型名稱 |
| html-no-noindex | 🟡 | 網站加 noindex |
| workflow-no-timeout／workflow-tee-no-mkdir | 🟡 | Actions 設時間預算、tee 前 mkdir |
| pwa-no-version | 🔵 | 前端每次改版更新 APP_VER |

這是啟發式掃描，會有誤報。刻意保留的寫法，在該行加註解 `guardrails: ignore`。

## 已知限制

- 複製過去的 `senior-frontend` 技能裡，`references/composition_map.md` 有幾個指向技能庫其他技能的
  相對路徑，在目標 repo 會連不到；那只是參考表，不影響技能運作。
- 這個 repo 若改成私人，其他 App 的工作階段就 `git clone` 不到了，要先在那個工作階段加入存取權。

## 疑難排解：CI 沒有跑

新建的 repo 要同時滿足兩件事，推送到 main 才會觸發 `CI Quality Gate`：

1. 預設分支是 `main`：https://github.com/xin7355-collab/skl/settings →「Default branch」。
2. Actions 已開啟：https://github.com/xin7355-collab/skl/settings/actions →
  「Allow all actions and reusable workflows」→ Save。

開啟 Actions 之前推送的 commit 不會補跑；開啟後要再推送一次，工作流才會出現在
https://github.com/xin7355-collab/skl/actions 。

「瀏覽技能」也可以先篩類別 → 「全選目前清單」→ 底部「讓 App 挑」，把候選清單丟給 App 篩選。

## 全自動影片剪輯

1. 手機開 https://github.com/xin7355-collab/skl/releases/new
2. 標籤填 `video-日期`（一定要 video 開頭），附上影片（最大 2 GB）。
3. 內文可寫（可省略）：`模式: short`（直式短影音）／`模式: 去空白`／`模式: 精華`、`長度: 45`。
4. 按 **Save draft**（草稿只有你看得到）。
5. 30 分鐘內，同一個草稿會出現 `檔名-edited-模式.mp4`；急的話到
   https://github.com/xin7355-collab/skl/actions/workflows/video-auto-edit.yml 按 Run workflow。

失敗會留 `.error1.txt` 說明並自動重試（最多 3 次）。精華是依鏡頭切換與音量挑選，不懂畫面內容；不含自動字幕。

https://xin7355-collab.github.io/skl/ai.html

## AI 模型自動切換（ai-model-router）

App 裡有呼叫 AI 時用：程式只寫等級，不寫模型名稱——`fast`（翻譯、摘要、分類）、`smart`（分析、推理）、
`best`（最難、程式）、`auto`（依內容自動判斷）。它會問官方現在有哪些模型、挑最新的；模型下架（404）自動換下一個；
429／5xx 指數退避；結果不合格自動升一級；全部失敗時給中文、可行動的錯誤，不印金鑰。支援 Groq、OpenRouter、Gemini、Claude。
組合安裝用 **ai**。Python 版給 GitHub Actions／後端，JS 版給網頁／Cloudflare Worker。

## Repo X-Ray（GitHub 專案透視）

https://xin7355-collab.github.io/skl/xray.html

- **三個分頁**（記住上次停在哪）：

  - **📚 紀錄**：看過（掃描或開 GitHub 頁面）、下載過（ZIP、Release、單檔下載）、⭐ 收藏的專案；可篩「收藏／下載過／外部專案」、
    在紀錄裡搜尋、複製收藏清單給 Claude 比較、清除紀錄（收藏保留）。只存在這支手機，不上傳。

- **🧾 白話重點**（取代原本的技術指紋、API 端點、檔案類型分佈）：用到什麼、會連到誰（只列認得的 AI／金流／資料庫／通知服務與資料來源 API）、
  要準備哪些金鑰（只讀 `.env.example` 的鍵名）、有付費服務時提醒設預算上限、能不能直接放 GitHub Pages、怎麼跑起來（可一鍵複製指令）、
  規模（Claude 能不能整包讀）。路由、目錄結構、依賴清單收在最下面「進階」裡，要時再展開。
- **說明文件一眼看懂**：「說明文件」清單每份檔案下面直接顯示一句話說明（技能讀 SKILL.md 的 description，
  一般文件讀第一段），開「翻成繁中」時自動翻成中文，不用一個個點開。捲到清單才讀取，走 raw 不花 API 額度；
  摘要記在手機，重看同一個專案不用再抓。最下面可「複製全部文件在做什麼」給 Claude，請它挑出對你有用的。
- **一個輸入框**：貼 GitHub 網址（或 `owner/repo`）→ 直接掃描；打關鍵字 → 搜尋專案。按「開始」才查，不會邊打字邊耗額度。
- **上一步不重查**：點結果後有「← 回到搜尋結果」；iPhone 左滑返回也可以。搜尋結果與專案資料存在手機 1 小時，
  重新整理、返回、再點一次都不花 API 額度。
- **檔案大小**：搜尋結果右側顯示每個專案的大小（GitHub 提供的 repo 大小，含歷史紀錄，約略值），可依大小、星數、最近更新排序。
- **最近紀錄**：最近 8 次搜尋與掃描，點一下就回來。
- **複製給 Claude 分析**、**分享結果**（網址帶 `?repo=`，別人打開直接看到同一個專案）。
- **⭐ 熱門推薦**：網站部署時（每天台灣時間 06:00）由工作流主動收集——歷來星數最高、本週／本月新星、熱門且正在更新、
  AI／大模型、Claude／Agent 技能，以及跟前一天比「🚀 竄升最快」。讀這份清單不耗你的 API 額度；
  收集失敗時沿用前一份並標示，完全沒有資料時改成點了才即時查詢。程式在 `web/build_trending.py`。
- **🌀 模糊搜尋**（開關會記住）：中文詞自動加英文同義詞（小說→novel、下載→download…）、拼錯一兩個字也找得到、
  依「每個詞都有對到」重新排序；仍然只用 1 次搜尋額度。
- **結果內模糊篩選**：在已載入的結果裡即時篩選（縮寫 nvl、拼錯 downlod 都行），不耗額度。
- **🧭 我的 App ＋ App 顧問**：「我的 App」分頁列出 `.github/apps.json` 的所有 App，點一下就掃描。掃描結果最上面的「App 顧問」
  依偵測到的訊號（有沒有工作守則、Actions、測試、PWA、爬蟲、資料庫、股票、影片、AI、機密檔…）對照
  `web/advisor_rules.json`，列出建議裝的 skl 技能（已裝的打 ✓）、該去 GitHub 搜的關鍵字（點了直接搜），
  以及兩個一鍵複製：「幫這個 App 裝建議的技能」「請 Claude 依診斷改善這個 App」——貼到那個 App 的 Claude Code 就會動手。
  全部在手機上分析，不會把報告公開；私人 App 要先在 Token 欄貼上唯讀 Token。改規則後跑 `python3 web/check_advisor_rules.py`。
- **🩺 一鍵健檢全部 App**：「我的 App」最後一顆按鈕。每個 App 約花 2 次 API 額度（15 個約 30 次，未登入每小時 60 次），
  依規則的 weight 加總成分數排序；每列可「看詳細」或「複製安裝」（依急迫程度最多 12 個技能），最後可複製全部的改善清單。
  私人 App 沒 Token 會略過並標示；額度用完會停下，列出還沒掃的 App 和恢復時間。
  **結果會記在這支手機**（標示「上次檢查」時間），重新整理或隔天打開都還在、不花額度；只有再按「重新健檢全部」才會重查。
- **返回會回到原本的清單**：從健檢清單或搜尋結果點進去後，按「← 回到…」或 iPhone 左滑返回，清單還在、而且捲回剛剛的位置。
- **🈯 翻成繁中**（預設開，可關）：搜尋結果、專案描述用 Google 翻譯（免費、不需金鑰，只送公開的專案描述）；
  熱門推薦的描述在每天收集時就先翻好。README 視窗有「🈯 中文」按鈕（程式碼區塊不翻，最多 400 行）。
  翻譯失敗會顯示原文並提示改用 Safari「aA → 翻譯成中文」。
- **這是什麼？為什麼沒網址？**：依名稱、描述、主題與檔案（SKILL.md、Markdown 比例、套件設定）判斷類型——
  AI 技能包、MCP 伺服器、資源清單、教學文件、命令列工具、函式庫、後端伺服器、瀏覽器擴充、App、網站、資料集、AI 模型；
  搜尋結果就有類型標籤，掃描後顯示「是什麼／沒網址的原因／怎麼用」，並可「🧩 複製『參考它做我的 App』」給 Claude。
- **成長速度（★/天）**：建立以來平均每天幾顆星，可排序，用來找「年輕但爆紅」的專案。
- 未登入的 GitHub 額度：一般 60 次／小時、搜尋 10 次／分鐘；加 Token（不勾任何權限）可到 5000／小時，Token 只放在記憶體。
- **記住 Token**：Token 區勾「記在這支手機」（預設勾），存在這支手機的瀏覽器（localStorage），下次自動帶入；畫面只顯示末 4 碼，
  只送到 api.github.com。同一個 xin7355-collab.github.io 網域的其他頁面也讀得到，所以只放唯讀 Token；不用時按「忘記 Token」。
  Token 失效（401）會提示重新產生。

## 每週維護報告（自動）

每週一台灣時間 08:00，`Weekly maintenance report` 工作流會：

1. 健檢 `.github/apps.json` 列的 App（防禦準則掃描）。
2. 比對上游技能庫有沒有新增／更新技能（基準在 `.github/upstream-sync.json`）。
3. 檢查網頁目錄有沒有缺中文說明或未分類的技能。

有要處理的才開一個 Issue「每週維護報告：待處理 N 項」（只寫數量，不寫問題內容）；全部正常就自動關閉，
不打擾你。要處理時在 skl 的 Claude Code 對話說「處理每週維護報告」。

私人 repo（例如 twns）預設不掃、標示「未設定權限」。要掃的話：到
https://github.com/settings/personal-access-tokens/new 建一個只對那個 repo 有 Contents 唯讀權限的 Token，
貼到 https://github.com/xin7355-collab/skl/settings/secrets/actions 新增名為 `SKL_READ_TOKEN` 的 Secret。

## 安裝技能時的兩個自動保護

- **安全掃描**：每個技能安裝前先用 skill-security-auditor 掃描；有危險寫法（FAIL）就不裝，
  只是有連網、讀寫檔案（WARN）會照裝但列出來。
- **開工自動健檢**：裝好的 App 每次開 Claude Code 對話，會先自動回報防禦準則問題數量；
  技能超過 14 天沒更新也會提醒。

## 把你做好的檔案做出來

直接把檔案（zip、Markdown、程式、規格、截圖都可以）上傳到 skl 或任何裝了技能的 App 的對話，說：

> 這是我做好的檔案，幫我做出來（做成技能／做成 App／放進某個 repo）。

Claude 會照 `file-intake` 技能的流程：全部讀過 → 安全掃描 → 判斷要做成技能、App 還是整合 →
實作＋自我測試＋瀏覽器實測 → 回報驗證過與沒驗到的地方，以及它替你做了哪些決定。
