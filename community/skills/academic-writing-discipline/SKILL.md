# 學術中文寫作品質稽核 SKILL

> **重要提醒**：以下判準是通用學術中文寫作原則的整理，不代表任何特定系所、期刊或指導教授的規定。使用前仍要對照自己系所的寫作規範與指導教授的個別要求，兩者衝突時以系所／教授為準。本 SKILL 只收錄站方原創、可獨立溯源於公開學術／方法學資源的判準，不含任何書籍、講座或未經授權的第三方框架與專有用語；如發現例外請回報。

**授權**：本 SKILL 由站方原創的判準與流程以 MIT License 釋出，可自由使用、修改、散布；引用自書籍、論文、官方文件與第三方資源的部分，著作權歸屬原作者，本授權不及於這些內容。

## 0. 套用範圍（先分清楚管什麼）

**本 SKILL 管什麼**：句子與用詞層級的寫作品質。具體來說——
- 因果動詞有沒有越線（橫斷面研究寫成絕對因果如「導致」、或因果與相關語言前後不一致——「影響」在商管領域是常見寫法，不列問題，見 `references/sentence-and-causal.md` §一）
- 句子構句是否清楚（話題有沒有漂移、有沒有中間肥大、弱動詞能不能還原、被動語態用得對不對）
- 用語是否符合台灣學術慣例（跟大陸用語的差異）
- APA 7 中文化格式對不對（內文引用、參考文獻、標點）
- 連接詞與標點是否符合台灣學術寫作慣例
- 有沒有 AI 生成文本的典型特徵
- 緒論／導論是否完成三個功能（CARS model 的三個 move）、方法章是否同時交代 How（怎麼做）與 Why（為何這麼做）、章節結構安排有沒有常見的誤解（見 `references/chapter-structure.md`；這一塊未經評測驗證，見下方說明）

**本 SKILL 不管什麼**：

1. 研究設計邏輯（研究問題該怎麼問、研究缺口怎麼分類與定位、方法論選擇是否恰當、量表構念的操作化是否合理）。這些屬於 `research-question-audit` SKILL 的範圍。
2. **文獻回顧的論證鏈是否成立**（v0.3.0 起移除）。原本有一套論證鏈四步與文獻對話四測試，2026-09-20 的評測顯示這一塊帶不來效益，而且在專門測假陽性的案例上把本來站得住的段落過渡誤判為論證斷裂，對使用者而言比沒有更糟。證據見 `evals/iteration-5/`。需要判斷論證撐不撐得住，請人工處理或另尋工具。

**`references/chapter-structure.md` 的評測狀態**：緒論缺研究缺口（CARS 的 move ②）這一項有測過（`evals/iteration-6/` 的 n5）。沒裝 SKILL 的模型本來就抓得到，但把這份檔案拿掉之後，Sonnet 3 次都沒抓到，回應寫明「論證是否站得住不在本次檢查內」：SKILL 的範圍一縮小，模型就把結構問題當成範圍外略過。所以它留著。方法章 How 與 Why、章節慣例誤解這兩塊仍沒有被評測測過。

**分工一句話**：這個 SKILL 檢查「這段話寫得對不對、像不像人寫的」；`research-question-audit` 檢查「這個研究問題問得對不對、缺口抓得準不準」。兩者可以先後套用在同一份文獻回顧草稿上，互不重疊。

## 1. 互動形態

**單輪結構化輸出**，不是多輪逼問：

1. 使用者貼一段中文學術文字進來（不需要先準備檔案、不需要提供檔案路徑）。
2. 依序套用第 2 節列出的判準，一次跑完。
3. 輸出結構化問題清單（見第 4 節格式），標明嚴重程度、原句、問題、改法。
4. 不寫入任何檔案到使用者的電腦，純對話輸出。
5. 不追問使用者「要不要看某一類判準」，除非使用者主動要求只看某一塊。

## 2. 判準總覽

| 判準類別 | 檢查什麼 | 詳細規則見 |
|---|---|---|
| 因果動詞紀律 | 橫斷面研究有沒有寫成因果；主張強度是否匹配證據強度與核對程度；表格與版面有沒有暗示因果；有沒有自創路徑名稱 | `references/sentence-and-causal.md` §一 |
| 構句原則 | 一句一話題、有沒有中間肥大、弱動詞能不能還原、被動語態用得對不對 | `references/sentence-and-causal.md` §二 |
| 台灣學術用語 | 是否誤用大陸用語（一般用語、統計術語）、地區用語對照 | `references/taiwan-usage-apa.md` §一 |
| APA 7 中文化 | 內文引用格式、參考文獻格式、APA 6/7 差異 | `references/taiwan-usage-apa.md` §二 |
| 連接詞與標點 | 連接詞是否濫用、標點是否符合台灣學術慣例 | `references/taiwan-usage-apa.md` §三 |
| 去 AI 感 | AI 生成文本典型特徵、形容詞拿掉論點站不站得住、正當／不當動機的界線 | `references/ai-flavor-and-common-errors.md` §一 |
| 常見錯誤速查 | 快速比對表，寫完後最後掃一遍用 | `references/ai-flavor-and-common-errors.md` §二 |
| 章節結構（緒論／方法章，未經評測驗證） | 緒論三功能（CARS model 三個 move）有沒有到齊；方法章 How 與 Why 是否都交代；文獻缺口是否誤放成獨立總結節、研究倫理是否誤放成方法章固定一節 | `references/chapter-structure.md` |
| 自檢 grep | 把上述判準轉成可執行的 grep 指令，供使用者在本機對整份稿件跑 | `references/grep-checks.sh` |

### 2.1 必掃清單（references 的最小子集，每次都要逐項掃過）

下列項目在評測中最常被漏掉，而且都是口試委員一眼就會看到的問題。完整規則仍在 references，這份清單只是底線：

- **因果動詞**：自己的橫斷面結果寫「導致」「造成」「決定」；同一句前半用因果語言、後半退回相關語言。「具有顯著正向影響」這類寫法在商管領域是慣例，不要誤抓；三條件（理論、迴歸或路徑分析、控制變數）只是讓它更站得住。引用隨機實驗時可用因果語言。
- **弱動詞與「存在」**：「存在……關係／差異」改成動詞句（「兩者顯著正相關」）；「進行／予以／加以＋動詞」還原成單純動詞。
- **大陸用語**：數據→資料、通過（介系詞）→透過、收集→蒐集、回歸→迴歸、人工智能→人工智慧、信息→資訊、被試→受試者、判別效度→區辨效度、模型擬合→模型適配、結果表明→結果顯示、用戶→使用者、優化→改善。
- **引用格式**：中文行文的敘述引用寫「等人」「與」，不寫 et al.、&。
- **標點**：中文句子用全形逗號、括號與「」引號。
- **譯名**：同一構念前後出現兩個譯名（例如知覺有用性與感知有用性）。

## 3. 執行步驟

1. 讀使用者貼的文字，判斷這段文字的性質（是量化研究的假說推導／討論？文獻回顧的一節？還是緒論／方法章的草稿？）——緒論或方法章草稿才套用 `references/chapter-structure.md`。
2. 動手前先用 Read 讀 `references/sentence-and-causal.md` 與 `references/taiwan-usage-apa.md`，文字有 AI 感疑慮時再讀 `references/ai-flavor-and-common-errors.md`；緒論或方法章草稿另讀 `references/chapter-structure.md`。只看本檔不讀 references 就輸出，是這個 SKILL 最常見的失敗：評測中 21 次執行有 2 次沒讀 references，其中一次漏掉了「人工智能」與「存在」濫用，整合修改版還把「人工智能」原樣留著。讀完後依序對照判準，逐條記錄違反處，並附上原文中的具體句子（不要只講「有問題」不指出是哪句）。
3. 把發現的問題分成致命／錯誤／瑕疵三級（見第 5 節判斷原則），輸出結構化清單。文字若含文獻引用，輸出必須附上誠實條款：本次稽核未核對被引用文獻原文，轉述是否偏離原意需使用者自行核對。轉述句裡出現原文才可能有的細節（樣本、情境、效果方向、數字），而使用者沒有附原文時，把它列進「待核對」，不要當成已確認。方法論文獻與理論原典的轉述，使用者沒附原文的也一律列進「待核對」（見 `references/sentence-and-causal.md` §一.4）。列進待核對的研究發現細節，整合修改版照使用者原句保留（可用〔待核對〕標出），不要自己換成較保守或較精確的說法。
4. 整合修改版寫完後，拿第 2.1 節的必掃清單再掃一次修改版本身，確認沒有把原文的用語、引用或標點問題原樣留下。
5. 若使用者要求在本機批次檢查整份文件，告知可使用 `references/grep-checks.sh`，並說明其中哪些指令需要人工判讀、哪些應該完全跑出空結果。

## 4. 輸出格式範例

```
## 學術寫作品質稽核結果

### 致命（因果動詞越線 / 學術倫理紅線）
- 原句：「知覺易用性導致使用意圖上升。」
  問題：這是橫斷面路徑係數，用「導致」超出證據能支持的因果強度。
  改法：「知覺易用性正向影響使用意圖（β = .xx）。」

### 錯誤（用語 / APA 格式）
- 原句：「本研究通過問卷收集數據。」
  問題：「通過」「數據」是大陸用語，台灣學術寫作慣用「透過」「資料」。
  改法：「本研究透過問卷蒐集資料。」

### 瑕疵（去 AI 感 / 構句可再優化，是否要修由使用者判斷）
- 原句：「⟨具體句子⟩」
  問題：連續幾句長度差不多，缺乏長短交錯，讀起來偏機器感。
  改法：⟨具體建議，例如把其中一句拆短，或併成一句較長的⟩

### 通過項目
- 因果動詞紀律：全篇未見越線動詞。
- APA 7 格式：內文引用格式正確，「等人」用法一致。

### 整合修改版
[把上面「致命」與「錯誤」的修法全部套用後，重新寫出一次完整、可以直接複製使用的句子——不要只留逐條局部修法，使用者要能直接拿這一版去用。瑕疵級的修法是否納入這個版本，依第 5 節的判斷原則決定，不強制。]

### 一句話總結
可用 / 需修（致命 N 處、錯誤 N 處、瑕疵 N 處）。
```

**「整合修改版」是必要輸出項，不是可省略的加分項**——使用者要的是能直接用的句子，逐條列問題只是說明過程，不能取代這一步。例外：使用者說明定稿要自己寫時，整合修改版改標「參考修改稿」，放在清單最後，讓使用者對照取用。

## 5. 三個等級的判斷原則

- **致命**：橫斷面研究寫「導致」這類排除其他解釋的絕對因果陳述（「影響」是商管慣例，不算這一類，見 `references/sentence-and-causal.md` §一）、同一句或同一節內因果與相關語言前後不一致、誇大原作者主張（把 "suggested" 寫成「證實」）、自創學術名詞偽裝成既有構念——這些是學術倫理層級的問題，原則上都要處理。
- **錯誤**：地區用語誤用、APA 格式明顯錯誤、同一構念交替使用兩個譯名、標點與引號不一致——這些會被口試委員抓到，應該修，但不涉及倫理紅線。
- **瑕疵**：句長不夠交錯、連接詞稍微工整、hedging 略多、段落結構稍微對稱、段落第一句就下結論——先問一句「修這個是不是在為了假設性問題增加不必要的複雜度」，傾向讓使用者自行決定要不要動，不要每一條瑕疵都當作必修項目列出來逼使用者處理。
- **不要誤抓領域慣用寫法**：「⟨作者⟩（年）提出⟨理論⟩」這類歸屬寫法，以及沿用原理論變數名稱的轉述，照用，不列問題；只有歸屬事實錯（被引的人其實沒有提出該理論）才列錯誤。
